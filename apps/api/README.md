# Syre Banks Fitness API

Requires Python 3.12+. Install from the repository root with `python3 -m venv .venv` then `.venv/bin/pip install -e 'apps/api[dev]'`.

The production database is PostgreSQL. Run from `apps/api` with environment variables or the repository `.env`. An explicitly selected local SQLite database works for development: `DATABASE_URL=sqlite:///./fitness-local.db ../../.venv/bin/alembic upgrade head`.

Start with `DATABASE_URL=sqlite:///./fitness-local.db ../../.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000`. `/health` checks process availability, `/ready` checks the database connection and `/docs` serves OpenAPI.

Checks from `apps/api`: `../../.venv/bin/ruff check .`, `../../.venv/bin/mypy app`, `DATABASE_URL=sqlite:///./fitness-test.db ../../.venv/bin/pytest`.

Production startup never creates tables automatically. Apply reviewed Alembic migrations before starting web/worker processes. PostgreSQL, Redis, S3 and configured mail/payment providers are required for their corresponding production features; local fallback testing does not validate a production deployment.

All list endpoints return `{items: [...], total: n}`. Records use UUID keys and UTC timestamps. Anonymous catalog/content routes exclude private records. Mutations require bearer identity; refresh/logout additionally require an allowlisted `Origin` and `X-CSRF-Token` matching the `sbf_csrf` cookie. Client ownership and assigned-coach scope are checked on the server for each record.

Development seed credentials must come from `SEED_ADMIN_PASSWORD` and `SEED_CLIENT_PASSWORD`, never from a constant in source. Demo records carry synthetic labels. Public photography represents illustrative licensed imagery unless actual coach media has been uploaded. No synthetic payment or subscription is treated as a verified sale.

The full API is organized into authentication, clients/onboarding, lead CRM, coaching, experience, scheduling, commerce, content/media, administration, private form checks and feedback. List endpoints support bounded pagination and return `items` plus `total`. OpenAPI documents the request models and bearer identity; root `docs/API.md` contains the browser contracts.

The local command should override both Docker-only database/cache hostnames: `DATABASE_URL=sqlite:///./fitness-local.db REDIS_URL=redis://127.0.0.1:6379/0 ../../.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000`. Development uses a bounded process-local rate-limit fallback when Redis is unavailable; production fails closed. `python -m app.seed` reads explicit seed credentials from configuration, preserves existing fixtures and refuses production.

Refresh cookies require an allowlisted Origin and the `sbf_csrf` value in `X-CSRF-Token`. Rotation revokes replayed families. Reset/deactivation/logout-all invalidate access tokens via a durable user token version. Password-reset and verification delivery return a clear unavailable error unless SMTP and Celery delivery are configured; tokens are never exposed through the public API.

A coach's explicit program assignment grants access to that assigned coaching snapshot, including manually arranged/offline coaching. Program access is scoped to the assignment owner and remains separate from template changes. Premium self-service live bookings require a verified subscription entitlement, a paid period covering the booking date and a remaining monthly allowance. Free consultation booking and coach-initiated business bookings are supported. Paid subscriptions are activated only after server verification matches transaction status, reference, currency and exact amount against the immutable order snapshot.

Invoice PDF downloads require bearer ownership/assigned-coach or administrator scope. Period-end cancellation requires `confirm: true`, preserves paid access until the term ends, and preserves payments/invoices. Standard checkout charges are one-time payments; recurring charges, refunds and provider subscription cancellation require further tested provider implementation. Unsupported provider operations return an explicit unavailable error. They never report a financial success.

Configured payment confirmation emails enter a durable outbox inside the activation transaction. Run the Celery worker and `celery -A app.core.jobs.celery_app beat` so pending outbox messages are retried when the broker is available. SMTP delivery, provider sandbox payments, PostgreSQL/Redis runtime, S3 and external calendar/video providers must be verified in a deployed environment before launch.

Media filenames are generated by the server, files remain private by default, and local signed URLs bind the media ID to an active, authorized identity and token version for five minutes. Type/signature/size checks apply; images additionally undergo structural verification and a 25 megapixel limit. Public transformations/testimonials require current, explicit publication consent and are removed from API output when consent is withdrawn. Accepted policies retain a text snapshot and legal edits require a new policy version.

Validation completed: Python 3.12 lint/type checks, meaningful API integration/security tests, all eight Alembic migrations on fresh SQLite with no metadata drift, PostgreSQL offline SQL generation, and rendered invoice PDF inspection. SQLite test success and offline SQL generation do not establish PostgreSQL concurrency or deployed provider behavior.
